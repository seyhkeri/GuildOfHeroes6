# Практическая работа №6. Связь двух классов. Состояние объекта (C#)

## Среда разработки и запуск
**Язык и платформа:** C# (.NET 8.0 / консольное приложение).
**Запуск программы:**
bash
dotnet run
  



## Структура решения

### 1. Учебная часть (Гильдия и поручения)
**Hero.cs** - класс героя из предыдущих работ. Хранит имя, уровень и баланс золота, предоставляет методы LevelUp() и AddGold(int amount) для безопасного изменения состояния.
**Guild.cs** - класс-контейнер гильдии. Хранит список героев List<Hero> и отвечает за их регистрацию, поиск и отчисление.
**Quest.cs** - класс разового поручения. Связывает поручение с конкретным героем через ссылку Hero? Assignee, проверяет условия допуска при старте в методе TryStart и изменяет состояние героя при успешном завершении в методе TryFinish().
**QuestBoard.cs** - класс доски поручений, связывающий коллекцию героев и список поручений. Управляет добавлением поручений, назначением героя по имени и закрытием поручений по идентификатору.

### 2. Личный проект
**Game.cs** - класс игры из предыдущих работ. Хранит название, жанр, год выпуска и рейтинг, а также метод UpdateRating(double newRating) для обновления оценки с проверкой диапазона 0.0–10.0.
**GameCatalog.cs** - класс-контейнер каталога игр. Хранит коллекцию List<Game>, выполняет добавление без дубликатов, поиск, удаление и подсчёт высокооценённых игр.
**ReviewSession.cs** - класс разовой операции обзора и оценки игры. Хранит ссылку на целевую игру Game? TargetGame, условие минимального года выпуска, предлагаемую оценку и признак завершения. Реализует безопасную привязку в TryStart(Game game) и обновление рейтинга игры в TryFinish().
**Program.cs** - точка входа с демонстрацией всех сценариев работы.

## Ответы на контрольные вопросы

### Шаг 6. Разница между TryStart и TryFinish
**Почему Quest меняет состояние героя в TryFinish, а не в TryStart:** метод TryStart фиксирует только факт принятия поручения, но работа ещё не выполнена. Награда и повышение уровня начисляются только в TryFinish, когда поручение успешно закрывается и все условия повторно подтверждаются.

### Шаг 9. Зачем проверять условия до изменения состояния
**Зачем в TryFinish все проверки ставятся до начисления награды и до IsCompleted = true:** это гарантирует целостность данных. Если изменить золото героя или поставить IsCompleted = true до проверки всех условий, то при возникновении ошибки или несоответствии требований объект окажется в некорректном состоянии, которое невозможно безопасно откатить.

### Шаг 11. Работа со ссылками в памяти
**Что произойдёт, если в AssignQuest создать нового Hero вместо найденного в Guild:** если передать в TryStart новый объект (new Hero(...)), то Quest сохранит ссылку на этот временный экземпляр, а не на героя из списка _heroes внутри Guild. В результате после вызова CompleteQuest золото и уровень прибавятся только у временного объекта, а оригинал в гильдии останется без изменений.

### Шаг 14. Личный проект
**Какое состояние меняет TryFinish и почему не раньше:** метод TryFinish обновляет рейтинг целевой игры и устанавливает флаг IsCompleted = true. Это происходит именно в TryFinish, а не в TryStart, так как TryStart только назначает игру на обзор, а итоговая оценка выставляется лишь после завершения обзора.
**Что произойдёт, если в TryStart по ошибке создать копию объекта:** если сохранить в TargetGame копию (new Game(...)) вместо ссылки на объект из GameCatalog, то TryFinish изменит рейтинг только у этой копии. Оригинальная игра внутри каталога сохранит прежний рейтинг, и последующий вызов catalog.FindGameByTitle(...) не покажет обновлённую оценку.
